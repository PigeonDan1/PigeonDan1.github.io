执行摘要

三个数据集上，模型的文本错误率（WER/CER）在 15.8%–20.2% 之间，但考虑说话人分配后的 cpWER/cpCER 明显更高， 说明说话人区分与切分是主要瓶颈。DER@0.25 介于 38.0%–48.7%%，且绝大多数错误来自说话人漏检（undercount）和时间戳漂移。

  • 文本质量：AISHELL-4 的 CER 最低（15.8%），AMI 与 AliMeeting 接近（约 20.2% / 19.6%）。删除错误普遍高于插入错误，模型倾向于“少说”。
  • 说话人区分：AMI 的说话人塌缩最严重（73.7% 欠估计、27.3% 严重塌缩），AliMeeting 与 AISHELL-4 也有 5.7%–18.1% 的严重塌缩。
  • 时间戳/切分：AliMeeting 与 AISHELL-4 的边界 MAE 超过 11 秒，且 undersegmentation 比例高；AMI 相对最好（1.68 秒）。
  • 端到端损失：AliMeeting 的 cpCER 比 flat CER 高出 19.0 个百分点，说明中文会议场景下时间-说话人联合建模仍是最大短板。

三个切分脚本都有同样的实现：

  • /cpfs/user/jingpeng/workspace/nfs/data/test/sa_asr/test_sa_asr/data_pre/pre_meta_jsonl_with_turns.py 第 502 行

原代码：

c_end = safe_float(chunk_utts[-1].get("end"), None)

该实现假设 chunk 内最后一个 utterance（按 start 排序）的结束时间即为 chunk 的结束时间。但在会议场景中，重叠语音非常常见：一个长 utterance 还没结束，另一个短 utterance 已经开始。按 start 排序后，后加入的短 utterance 可能排在后面，但它的 end 却早于前面那个长 utterance。脚本把这个较短的 end 当作 chunk_end 去截断音频，却保留了完整长 utterance 的参考文本，造成音频被截断、参考标注“悬空”。

已修复：将 c_end 改为 chunk 内所有 utterance end 的最大值：

c_end = max((safe_float(u.get("end"), None) for u in chunk_utts), default=None)

并在切分后增加校验：如果参考最大结束时间超过实际音频时长 0.5s 以上，打印警告。

根因分析 2：分析代码把 start=0.0 的句子错误排到最后

/cpfs/user/jingpeng/workspace/dots_post_train/evaluation/evaluate_sa_asr_meeteval.py 原第 79 行：

rows.sort(key=lambda x: (safe_float(x.get("start")) or 1e18, safe_float(x.get("end")) or 1e18))

当 utterance 的 start=0.0 时，safe_float 返回 0.0，而 0.0 or 1e18 会把 0.0 当 falsy 处理，导致这些句子被排到末尾。于是 build_reference_segments 把第二个句子的开始时间误当作 chunk_start，让包含首句的 chunk 产生负时间戳（例如 ES2004c_chunk_00000_00006 中首句相对时间变成 -17.379s）。这个 bug 只影响可视化与检测，并不会让音频被截断。

已修复：新增 _sort_key 把 0.0 视为合法开始时间；同时 chunk_start 显式取选中 utterance 的最早 start。

结论与建议

已识别的关键问题

  • 数据切分缺陷：AMI 预处理脚本在重叠语音场景下错误取最后一个 utterance 的结束时间作为 chunk 结束时间，导致 17 个 AMI 样本（以及少量 AliMeeting/AISHELL-4 样本）音频被截断但参考文本仍保留完整内容。需修复切分逻辑并重新生成测试数据。
  • 说话人塌缩是首要问题：三数据集均出现严重的说话人欠估计，模型倾向于把多个说话人合并为 1–2 个主导说话人。这与训练目标中 speaker-aware 损失权重不足或数据增强不足有关。
  • 删除型错误占主导：删除率显著高于插入率，模型在复杂声学环境下“保守”地省略内容；当参考说话人数较多时，文本损失进一步放大。
  • 中文远场时间戳漂移严重：AliMeeting 与 AISHELL-4 的边界 MAE 超过 11 秒，undersegmentation 比例高，模型难以在远场、混响、重叠语音中精确定位说话人切换。
  • 重复与格式问题：AliMeeting 重复问题率达 58.2%，且存在约 1% 的 JSON 结构损坏；需关注解码稳定性与输出格式约束。
  • 结尾截断/拖尾：平均结尾误差 6–9 秒，部分样本超过 30 秒，说明模型对长段结尾的说话人终止不敏感。

可落地的优化建议

  • 修复测试数据切分：将 chunk_end 改为 chunk 内所有 utterance 结束时间的最大值；生成后校验 ref_max_end ≤ audio_duration + 0.5s；重新跑评估。
  • 增强说话人区分能力：在损失函数中加入更硬的 speaker-count 约束或 speaker-embedding 对比损失；针对 3+ 说话人场景做专门数据采样与课程学习。
  • 降低删除率：引入基于字/词覆盖的奖励或惩罚，抑制过度省略；对低信噪比、远场样本做前端增强或领域适配。
  • 改进时间戳与切分：联合优化边界定位（boundary detection）与说话人二值化；在 0.25s 与 0.5s 多尺度上评估并加权边界损失。
  • 抑制重复与稳定输出：调整解码温度、重复惩罚；对输出格式做严格 JSON schema 约束和后校验，减少 1% 左右的格式损坏。
  • 分场景评估与迭代：按说话人数（1/2/3/4+）、重叠度、信噪比分层看指标，优先优化高 DER 样本聚集的桶。
